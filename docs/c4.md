# C4 model

Levels 1 to 3. Level 4 (code) is the source itself and is not duplicated here.

## Level 1 - System context

```mermaid
flowchart TB
    USER["Evaluator / operator<br/>watches and reconfigures"]
    SYS["Neighbourhood Energy Simulation<br/>simulates 30 houses and 6 public chargers,<br/>accounts for the energy, visualises it"]

    USER -->|"watches the dashboard"| SYS
    USER -->|"sets seed and proportions"| SYS

    note["No external systems.<br/>No weather API, no market data, no auth provider.<br/>Deterministic and self-contained by design (A-009)."]
    SYS --- note
```

The absence of external systems is a decision, not an omission. The assignment
asks for privacy-friendly and deterministic behaviour, and every external
dependency is a source of non-reproducibility.

## Level 2 - Containers

```mermaid
flowchart LR
    BROWSER["Browser<br/>two static pages, vanilla JS"]
    API["Sim.Api container<br/>ASP.NET Core, .NET 10<br/>REST + background worker"]
    DB[("SQLite file<br/>configuration + projections")]

    BROWSER -->|"GET /api/simulation, ~4/s"| API
    BROWSER -->|"PUT /api/simulation/configuration"| API
    API -->|"reads and writes"| DB
```

One deployable. The tick loop is a `BackgroundService` inside the API container
rather than a separate worker - see ADR-0004 for why that seam exists but is
not yet split.

## Level 3 - Components, and where the boundaries are

```mermaid
flowchart TB
    subgraph driving["Driving adapters"]
        REST["SimulationEndpoints<br/>handlers delegate, no logic"]
        WORKER["SimulationWorker<br/>drives the clock"]
    end

    subgraph app["Application - orchestration and translation"]
        ENGINE["SimulationEngine<br/>the only place all three contexts meet"]
        ACL["ContextTranslator<br/>anti-corruption layer"]
    end

    subgraph contexts["Bounded contexts - one aggregate root each"]
        SIM["Simulation<br/>SimulationRun<br/>clock, weather, season"]
        ENERGY["Energy<br/>Neighbourhood<br/>houses, assets, physics"]
        ACC["Accounting<br/>EnergyLedger<br/>cumulative kWh, settlement"]
    end

    SK["SharedKernel<br/>Kilowatts, KilowattHours, noise"]

    subgraph driven["Driven adapters"]
        CFG["SqliteConfigurationStore"]
        PROJ["SqliteProjectionStore"]
        BUS["InProcessTickBus"]
    end

    REST --> ENGINE
    WORKER --> ENGINE
    ENGINE --> ACL
    ACL --> SIM
    ACL --> ENERGY
    ACL --> ACC
    SIM --> SK
    ENERGY --> SK
    ACC --> SK
    ENGINE -.->|"port"| CFG
    ENGINE -.->|"port"| PROJ
    ENGINE -.->|"port"| BUS
```

The three context boxes have **no arrows between them**. That is the whole
point: `Sim.Energy` has no project reference to `Sim.Accounting`, so the arrow
cannot be drawn even by accident (ADR-0001). Everything crossing between them
passes through the translator.

## One tick, end to end

```mermaid
sequenceDiagram
    participant W as SimulationWorker
    participant E as SimulationEngine
    participant S as SimulationRun
    participant T as ContextTranslator
    participant N as Neighbourhood
    participant L as EnergyLedger
    participant P as Projections

    W->>E: Tick()
    E->>S: Advance()
    S-->>E: TickEnvironment (instant, weather, season)
    E->>T: to MeasurementContext
    Note over T: drops season and cloud cover
    E->>N: Measure(context)
    N-->>E: 62 MeterReadings (signed kW)
    E->>T: to EnergyEntry
    Note over T: asset type becomes consumer or generator
    E->>L: Post(entries)
    L-->>E: GridSettlement (import xor export)
    E->>P: append point, save meter totals
    E->>E: publish TickCompleted on the bus
```

Two translation points, both in the application layer, both deliberately lossy.
Note also that `Neighbourhood` returns readings and nothing else - it measures
but does not account. Settlement is `EnergyLedger`'s job.

## The dependency rule

```mermaid
flowchart LR
    API2["Sim.Api"] --> INFRA["Sim.Infrastructure"] --> APP2["Sim.Application"] --> CTX["Simulation / Energy / Accounting"] --> SK2["SharedKernel"]
```

Dependencies point inward only. `SharedKernel` references nothing. The contexts
reference only `SharedKernel`. No context references ASP.NET, SQLite or any
other infrastructure type.

Currently enforced by project references. An architecture test that locks it
against future edits is outstanding work (TASK-008).
